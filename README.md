# 실시간 소음 분석 (현장용 웹앱)

휴대폰 마이크로 소음을 **실시간 분석**하는 웹앱(PWA)입니다. 설치 없이 링크로 열고, "홈 화면에 추가"하면 앱처럼 쓸 수 있습니다. 안드로이드(크롬)와 아이폰(사파리) 모두 됩니다.

## 화면

**실시간 분석 (기본 화면)**

- **맨 위 보기 전환**(아이콘, 아래에 이름): **주파수 + 시간축**(기본) / 스펙트로그램 / 1/3 옥타브
- **레벨 판**: 색 막대(초록 → 노랑 → 빨강, 빨강은 경고 기준 이상, 밝은 칸 하나는 최대), 큰 숫자로 **지금 소음**, 그 아래 **최소 · 평균 · 최대**.
  왼쪽 ⓘ 는 화면 보는 법, 오른쪽 ↻ 는 초기화(최소·평균·최대·최대 스펙트럼·녹음 버퍼 다시 시작)
- **기본 화면은 그래프 두 개**: 위에 큰 **주파수 그래프**(주파수–dB), 아래에 작은 **시간축 그래프**(시간–dB, 그래프 칸의 약 1/3), 사이에 구분선
- **주파수 그래프 (FFT 스펙트럼)**: 가로축 주파수 **20 Hz – 20 kHz**(로그) 또는 0 – 20 kHz(선형), 세로축 **주파수 가중치를 적용한 dB**(기본 A특성 dB(A))
  - 모양 **면**: 빨강 = 지금, 회색 = 피크 홀드 / **선**: 파랑 = 지금, 빨강 = 피크 홀드 / **막대**: 면과 같은 색의 막대
  - 어느 모양이든 주황 선 = 미니멈 홀드, 분홍 점선 = 최대값 추적, 연주황 점선 = 최소값 추적
  - 뚜렷하게 튀는 주파수 2개에 "1,250 Hz"처럼 표시하고, 오른쪽 위에 가장 큰 피크를 보여 줍니다.
- **십자선 커서**: 그래프를 누르면 세로·가로 선이 곡선과 만나는 점에 "A 1,241 Hz / 56.5 dB(A)"를 띄웁니다. 한 번 더 누르면 커서 B, 아래 줄에 두 값과 차이(B−A). 끌어서 옮기고 × 로 지웁니다.
- **스펙트로그램**(따로 선택하는 보기): 같은 주파수 축에서 시간에 따른 변화를 색으로 보여 줍니다. 맨 위가 지금이고 아래로 흘러갑니다.
- **1/3 옥타브**: 25 Hz – 20 kHz 30개 대역 막대(대역 안 FFT 칸의 에너지 합), 대역별 최대 표시, 맨 오른쪽에 **전체** 막대
- **시간축 그래프**(주파수 그래프 아래): 가로 측정 시간, 세로 소음 크기(큰 숫자와 같은 Fast 값, 0.05초마다)인 선 그래프. 최근 30초 · 1분 · 5분이 오른쪽으로 흘러가고, 점선은 평균입니다.
  일시정지하면 함께 멈추고, 초기화하면 새로 그립니다.
- **차트 메뉴(⚙, 그래프 오른쪽 위)**: 누르면 바로 아래에 메뉴가 열립니다(바깥을 누르면 닫힘).
  - **차트 스타일**: 면 / 선 / 막대
  - **최대값 추적**: 최근 큰 값을 따라가다 초당 12 dB씩 내려오는 점선(지나간 큰 소리의 흔적)
  - **최소값 추적**: 최근 작은 값을 따라가다 초당 12 dB씩 올라오는 점선(바닥 소음의 흐름)
  - **피크 홀드**: 초기화 뒤 가장 큰 값 / **미니멈 홀드**: 초기화 뒤 가장 작은 값(주황)
  - **홀드 재설정**: 위 선들만 새로 시작(최소·평균·최대, 시간축 그래프는 그대로)
  - **가중치 · 시간축 · FFT · 축**: 주파수 가중치 **A / C / Z**, 시간축 그래프 길이(30초 / 1분 / 5분), FFT 크기(2048 / 4096 / 8192 / 16384), 주파수 축(로그 / 선형)
  - 미니멈 홀드를 켜고 저장하면 기록·공유 이미지에도 주황 선이 남습니다.
  - A: 보통 소음(사람 귀에 가깝게) · C: 엔진·부밍음처럼 저음이 큰 소리 · Z: 거르지 않은 소리. 바꾸면 최소·평균·최대가 새로 시작합니다.
- 세로: 위에서부터 보기 전환, 레벨 판, 그래프(남는 높이 전부), 버튼(녹음 ┃ 측정·저장). 가로: 그래프가 화면 가득, 레벨 판은 그래프 왼쪽 위에, 버튼·보기 전환·메뉴는 아래 한 줄

**버튼** (두 묶음으로 나뉨): ● **녹음**(빨강) ┃ ▶⏸ **측정 시작 / 일시정지**(화면과 값 고정) · ⬇ **저장**(지금 스펙트럼과 값, **방금 들린 소리**를 차량번호·메모와 함께 저장)

**녹음은 측정과 따로 움직입니다**: 누른 때부터 정지할 때까지 녹음합니다(최대 5분). 녹음 길이는 그래프 위 빨간 "● 녹음 00:12"에 따로 나오고, 위쪽 상태·시계는 측정 시간 그대로입니다.
측정을 일시정지해도 녹음은 계속되고, 녹음 버튼이 일시정지를 풀지도 않습니다(측정 전이면 마이크만 켭니다). 정지하면 측정은 그대로 이어지고, 녹음은 **파일** 탭에 들어가며 알림의 **분석 보기**를 누르면 바로 녹음 전체를 분석합니다.
녹음 중에 다른 탭으로 가면 그때까지 녹음한 소리가 파일 탭에 남습니다.

**녹음 함께 저장**: 앱은 늘 최근 소리(기본 10초)를 기억하고 있어서, 이상한 소리가 난 **뒤에** 저장을 눌러도 그 소리가 남습니다. 기록 화면에서 다시 듣고, 그 소리의 스펙트로그램과 시간축 그래프를 재생 위치와 함께 보고, WAV 파일로 보낼 수 있습니다.

**파일 분석** (아래 탭 "파일"): 음원·녹음 파일(mp3, m4a, wav, aac, ogg, 동영상의 소리 등)을 열면 파일 전체를 분석합니다.

- 평균(Leq)·최대·최소, 전체 평균·최대 스펙트럼과 피크, 가장 큰 순간
- 파일 전체의 **스펙트로그램**과 **시간축 그래프**(시간별 dB). 누르면 그 시점으로 이동해 들을 수 있습니다.
- 재생하면 스펙트럼이 **재생 위치의 소리**로 바뀌고, 두 그래프에 재생 위치 선이 따라갑니다.
- 레벨 기준: **보정 dB**(이 휴대폰 보정값 적용, 녹음 파일용) / **파일 dBFS**(디지털 크기, 음원용), 가중치 A / C / Z
- 커서 A·B, 면/선/막대, 로그/선형 그대로 사용. 미니멈 홀드를 켜 두면 전체 최소도 주황 선으로 보입니다. **기록에 저장**하면 파일(30MB 이하)도 함께 남습니다.
- 처음 5분까지 분석하고, 파일은 휴대폰 안에서만 처리됩니다.

**기록**: 저장한 분석 목록, 상세 화면(스펙트럼 + 커서, 값, 소리), 결과 이미지·요약 글 공유(카톡 등), 엑셀(CSV) 내보내기

**설정 (관리자 비밀번호, 처음 값 `0000`)**: 회사 이름, 저장할 때 남길 소리 길이(없음/5/10/20/30초), 경고 기준(색 막대 빨강), **마이크 보정**, 비밀번호 변경, 기록 삭제

## 마이크 보정

휴대폰마다 마이크 감도가 달라서 **기기마다 한 번씩** 보정해야 값이 맞습니다.
설정 → 마이크 보정: 정밀 소음계와 나란히 두고 5초 측정 → 소음계 값 입력 → 적용. 보정값은 그 휴대폰에만 저장됩니다.

## 배포 (GitHub Pages, 무료)

마이크는 https 주소에서만 켜지므로 웹에 올려야 합니다.

1. 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿉니다.
2. 기본 브랜치에 코드가 올라가면 `.github/workflows/pages.yml` 이 테스트 후 자동 배포합니다.
3. 주소는 `https://<계정>.github.io/<저장소>/` 형태입니다.

앱을 고친 뒤에는 `sw.js` 의 `VERSION` 을 올려야 휴대폰에 새 버전이 들어갑니다.

## 측정 방식

- **레벨**(현재·평균·최대·최소): 마이크 신호를 **A특성 또는 C특성 디지털 필터**(IEC 61672 곡선, Z는 거르지 않음)로 거른 뒤 표본 하나하나로 계산합니다.
  현재·최대·최소는 Fast(125 ms) 시간 가중, 평균은 Leq입니다. 시작·초기화·가중치 변경 후 0.5초는 필터 안정화를 위해 버립니다.
- **스펙트럼**: Web Audio AnalyserNode의 FFT(블랙만 창) 각 칸에 창 보정과 가중치, 보정값을 더한 칸별 dB입니다.
  모든 칸을 더하면 전체 소음도가 됩니다. 그래서 칸 하나의 값은 전체 소음도보다 낮고, FFT 크기를 키우면 칸이 좁아져 값이 더 낮아집니다.
- **1/3 옥타브**: 같은 칸별 값을 대역(중심 1000·2^(n/3) Hz, 25 Hz – 20 kHz)마다 에너지로 더합니다. 낮은 대역에도 칸이 들어가도록 이 보기에서는 FFT 16384(약 2.9 Hz 간격)로 계산합니다.
- **홀드·추적**: 시작·초기화 뒤 0.5초가 지나고부터 FFT 칸마다 최대·최소를 기억하고(피크·미니멈 홀드), 추적 선은 새 값이 넘으면 바로 따라가고 아니면 초당 12 dB씩 지금 값 쪽으로 돌아옵니다.
- **피크**: 약 1초로 평균한 스펙트럼에서 주변(±1/3옥타브, 저음에서는 최소 ±12칸)보다 6 dB 이상 튀는 곳을 찾습니다.
- **녹음**: AudioWorklet이 마이크 원음을 최근 N초 순환 버퍼에 담아 두고, 저장할 때 16비트 WAV로 만듭니다(10초에 약 1MB).
  녹음 버튼을 누르면 같은 원음을 0.5초씩 보내 모아 두었다가 정지할 때 WAV로 만듭니다(5분에 약 29MB). 압축하지 않으므로 분석 값이 실시간 값과 같습니다.
  일시정지는 화면·값과 "저장"용 버퍼만 멈추고, 녹음은 멈추지 않습니다.
- **파일·저장된 소리 분석**: 브라우저가 파일을 48 kHz 모노로 풀고, 실시간과 같은 가중치 필터·Fast 검파로 레벨을,
  같은 규칙(블랙만 창 FFT 4096, 칸별 dB)으로 스펙트럼을 계산합니다. 긴 파일은 프레임 간격을 늘려 최대 1,500장으로 나눕니다.
- 브라우저의 에코 제거·잡음 제거·자동 음량 조절은 끄고 받습니다.

## 알아 둘 점

- **스마트폰 측정값은 참고값입니다.** 법정 측정(정밀 소음계)을 대신하지 않습니다.
- 휴대폰 마이크는 대략 30–100 dB 범위에서 쓸 만하고, 아주 큰 소리에서는 포화될 수 있습니다(저장된 기록에 경고 표시).
- 화면이 꺼지거나 다른 앱으로 바뀌면 측정이 멈추고, 돌아오면 새로 시작합니다. 측정 중에는 화면이 꺼지지 않게 합니다.
- 기록은 **그 휴대폰 브라우저 안에만** 저장됩니다. 필요하면 엑셀 파일로 보내 두세요.

## 개발

빌드 도구·외부 라이브러리 없이 HTML/CSS/자바스크립트 모듈로 되어 있습니다.

```
index.html              화면 틀 (아래쪽 탭: 분석 / 파일 / 기록 / 설정)
css/app.css             스타일 (검정 계열, 세로·가로 배치)
js/app.js               화면과 이동 (실시간 분석, 기록, 저장된 기록, 설정)
js/meter.js             마이크 측정 엔진 (Web Audio, 가중치 A/C/Z, 녹음)
js/level-processor.js   AudioWorklet: 가중치 필터, Leq, Fast 최대·최소, 소리 버퍼·녹음
js/spectrum.js          FFT 스펙트럼 그래프 (캔버스, 면/선/막대, 홀드·추적 선, 십자선 커서, 실시간·기록·공유 이미지 공용)
js/spectrogram.js       스펙트로그램 (실시간 흐름, 저장된 소리 + 재생 위치)
js/octave.js            1/3 옥타브 막대 그래프
js/levelbar.js          LED 색 막대
js/audio.js             WAV 만들기·읽기, 소리 파일 풀기(mp3·m4a 등)
js/analysis.js          파일 전체 분석 (레벨 이력, 평균·최대 스펙트럼, 프레임별 스펙트럼, 피크)
js/timeline.js          시간축 그래프 (파일·기록용, 실시간용)
js/dsp.js               신호처리 순수 함수 (A·C 필터 설계, 칸별 dB, 1/3 옥타브 대역, 피크, 리샘플링, FFT·STFT)
js/settings.js          설정 저장
js/store.js             기록 저장 (IndexedDB)
js/share.js             공유 이미지, 요약 글, CSV
js/format.js            표시 형식
sw.js, manifest.webmanifest, icons/   오프라인·홈 화면 설치
```

```bash
npm start                       # http://localhost:8080 (localhost 에서는 마이크 허용됨)
npm test                        # 신호처리 단위 테스트 (Node 22, 설치 불필요)
NODE_PATH=$(npm root -g) npm run test:e2e   # 크롬에 테스트 음을 마이크로 넣어 전체 흐름 확인 (playwright 필요)
```

E2E 테스트는 1 kHz·100 Hz 테스트 음(레벨을 아는 WAV)을 가짜 마이크로 넣고, 앱이 표시한 dB(A)·dB(C)·dB(Z)와 피크 주파수가 계산값과 맞는지,
커서가 1 kHz를 맞게 읽는지, 주파수 그래프 아래 더 작은 시간축 그래프, 세 가지 보기, 차트 메뉴(스타일·추적·홀드·홀드 재설정)와 그래프 설정, 일시정지·초기화, 소리와 함께 저장·재생·WAV 보내기, 보정,
녹음이 측정과 따로 움직이는지(일시정지 중 녹음 시작·계속, 정지 후에도 측정 계속)와 녹음 → 파일 분석이 제대로 되는지 확인합니다.
파일 분석은 1 kHz 3초 + 100 Hz 3초 파일을 열어 Leq(에너지 평균)·최대·최소, dBFS 전환, 그래프를 눌러 이동, 기록 저장을 확인하고, 세로·가로 화면을 캡처합니다.
